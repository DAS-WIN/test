## 架構

| 模組 | 責任 |
| --- | --- |
| Core / Models | 統一資料模型、單位、驗證與啟動參數 |
| MinerController | 單一非同步鎖序列化啟停與排程，只管理自己建立的程序 |
| RestartScheduler | 單調時鐘倒數；運行、停止中、等待、啟動中與錯誤狀態 |
| ApiReader | loopback HTTP、3 秒完整逾時、2 MB 上限、不跟隨重新導向 |
| NvidiaSensors | 透過 PCI bus 合併 nvidia-smi 感測資料 |
| ExecutableProbe | 10 秒上限、輸出大小上限、演算法／GPU 清單解析 |
| WPF App | MVVM、三頁視圖、設定草稿、DPAPI、系統匣、示範與匯出 |
| TrendChart | 原生向量圖表，缺失資料與不同統計階段不連線 |
| Tests | 替身程序與可控制時鐘，不啟動真正挖礦 |

## 行為

- 真實／示範模式分離，示範不儲存假的執行檔與錢包。
- 可保存未完整草稿，啟動時才檢查必填；儲存不改變運行中的礦工與其監控 port。
- 演算法讀取去重、快取、失敗保留；更換檔案提示重新讀取。
- 按鈕依狀態與程序擁有權啟用；啟動前檢查 API port，避免重複啟動。
- 正常停止向受管理 console 發 CTRL_C，10 秒後才終止程序樹，再最多等待 5 秒。外部程序不被終止。
- 確認完全停止後才開始排程等待。手動停止取消、手動重啟重新計時、一次性執行完成後關閉、異常退出暫停。
- 重開不啟動礦工或排程；關閉視窗縮至系統匣，停止並退出才結束。
- 歷史保留 6 小時，平均只取最新統計階段的有效樣本，顯示實際樣本時間跨度。
- 設定先寫暫存檔再替換，密碼 DPAPI；設定讀取失敗保留原檔，單純退出不覆寫。

## 驗證邊界

已在 Linux 執行 .NET 10 核心測試、完整 WPF 交叉編譯與 Windows x64 發布。Windows 視窗、系統匣、DPAPI、CTRL_C 及實際 GPU／礦池端到端行為仍需 Windows 實機。交叉編譯不等於實機驗收。

`scripts/Smoke-Windows.ps1` 可在 Windows 巡覽三頁與排程面板，檢查 WPF binding errors 並輸出 PNG。CI 設定包含此步驟；本機新增 workflow 不代表遠端 CI 已執行。
