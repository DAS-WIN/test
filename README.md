# SRBMiner Monitor

目前版本：**0.2.2**。完整程式碼與使用說明集中在 `main`。

[下載 Windows x64 可攜式套件](https://github.com/DAS-WIN/test/releases/download/v0.2.2/SRBMinerMonitor-0.2.2-win-x64.zip) · [所有保留版本](https://github.com/DAS-WIN/test/releases)

繁體中文 Windows 桌面監控程式，使用自己的 SRBMiner BAT 啟動礦工。深灰／青藍介面包含總覽、挖礦設定與事件紀錄；本版已移除示範模式，以及演算法、錢包、GPU 等表單啟動方式。

## 使用現有 BAT

1. 完整解壓縮 Windows x64 套件，執行 `SRBMiner Monitor.exe`；啟動 GUI 不會自行挖礦。
2. 挖礦設定選「選擇現有 BAT」，選擇 `.bat` 或 `.cmd`。
3. 如果未啟用 API，點「建立監控副本」，存於原 BAT 相同資料夾；原檔保留，只補 API 參數。
4. 按「儲存並啟動 BAT」。礦工在背景執行，不顯示獨立 CMD 視窗。

## 貼上自己的 BAT

1. 挖礦設定選「貼上 BAT 內容」。
2. 選擇礦工資料夾，貼上完整 BAT；例如使用 `%~dp0SRBMiner-MULTI.exe` 的批次檔，資料夾應包含該執行檔。
3. 按「儲存並啟動 BAT」。程式自動補上 `--api-enable --api-port`，其他挖礦參數保留。

貼上模式會在指定資料夾建立唯一名稱的暫存 BAT，因此 `%~dp0`、`cd /d` 與 `logs` 等相對路徑保有原意；停止後移除暫存 BAT。內容以 Windows 使用者 DPAPI 加密存入設定，不能直接搬至另一個 Windows 帳號解密。原有 BAT 檔案不會被貼上內容覆寫。

GUI 不包含礦工，請自行安裝 [官方 SRBMiner-Multi](https://github.com/doktor83/SRBMiner-Multi/releases/tag/3.8.0)。僅支援單一演算法，不調整超頻或風扇設定。

## 更新頻率與總覽

- 硬體資訊（算力、功耗、效率、溫度、風扇、時脈及趨勢）依同一更新間隔整批刷新，預設每分鐘 :00。首筆、新礦工階段或修改間隔時立即顯示一筆。
- 挖礦設定可手動輸入 1–10000，選秒／分／時／天；按「儲存設定」立即套用，不必重啟礦工。
- 「最近成功分享」只顯示收到的 CMD 原始成功訊息，不填入 API 確認文字。Accepted／Rejected 數字仍每秒核對 API，不受硬體更新間隔影響。
- 硬體感測值由本機 `nvidia-smi` 於硬體更新時取得，依 PCI bus 對應；未知值顯示 —。API 維持每秒核對分享，完整請求逾時 3 秒且不重疊。
- 最近成功分享位於總算力上方；綠底的成功分享統計條已刪除。Accepted 數仍顯示於顯卡下方的分享統計。
- 礦池只顯示位址與來源。可展開「礦工即時輸出」查看最近 500 行原始輸出。
- 算力／功耗／溫度趨勢可選 15 分鐘、1 小時、6 小時。斷線不補值，重啟有分界。

API 與輸出的累積計數採用同一階段較新的觀測值，不將兩份計數相加。重啟後重新計數。單卡可使用 API 總計，多卡從明確 GPU ID 的輸出取得每卡統計。

## 事件紀錄

只保留 CMD 原始輸出提供的分享成功 Accepted、失敗 Rejected／failed、逾時 Timeout。算力表、分隔線、Job received、連線、啟停與排程訊息不加入事件列表或事件匯出。API 請求逾時不當成分享逾時。

事件保留最近 2000 筆，顯示及匯出目前篩選的最近 500 筆。啟動與排程狀態仍在總覽及通知文字顯示；技術錯誤寫入啟動診斷紀錄。

## 重啟與退出

「停止礦工」只停止 BAT 及其受管理子程序，「重啟礦工」則重新啟動它們，GUI 保持開啟。停止訊號由獨立輔助程序發送，GUI 不會接入礦工主控台。自動重啟為：運行指定時間 → 完全停止礦工 → 等待指定分鐘 → 重新啟動，可循環或只執行一次。手動停止取消排程；停止失敗會暫停排程；非預期退出會依排程的等待分鐘倒數重啟，啟動失敗則重新倒數再試。

只控制本程式啟動的礦工；礦工停止後暫停 API 與感測器查詢，保留最後一筆畫面，重新啟動後才恢復更新。Windows Job 追蹤 BAT 與 `start /b` 等子程序，先嘗試正常停止，10 秒後才終止受管理程序樹。關閉視窗縮至系統匣；選「結束應用程式」才結束。

設定在 `%LOCALAPPDATA%\SRBMiner Monitor\settings.json`；舊版 BAT 路徑與排程設定保留，舊表單欄位忽略。GUI 重新開啟不會自行啟動礦工或啟用排程。

## 建置與診斷

需 .NET 10 SDK；Windows x64 發布包含 runtime，不需另裝 SDK。

```powershell
dotnet build SrbMinerMonitor.slnx -c Release
dotnet test tests/SrbMinerMonitor.Tests -c Release
pwsh ./scripts/Smoke-Windows.ps1
pwsh ./scripts/Publish-Windows.ps1
```

若無法啟動，執行 `Start-Diagnostics.cmd`，查看 `%LOCALAPPDATA%\SRBMiner Monitor\Logs\startup-*.log`，無法寫入時改用 `%TEMP%`。升級時先停止舊版並完整解壓新版到新資料夾，不要只替換 EXE。

Windows 整合測試使用不挖礦、不連礦池的測試程序。真實 Windows 與實際 GPU 的接受結果需實機試跑。詳見 [版本變更](docs/RELEASE-NOTES-0.2.2.md)、[資料來源](docs/DATA-SOURCES.md) 與 [驗證說明](docs/VERIFICATION.md)。

挖礦設定新增「礦工非預期退出後自動重啟」（預設關閉），儲存即套用。單獨啟用時意外退出後等待 10 秒重啟，無須定時排程；兩者同時啟用時以排程等待時間為準。手動停止會取消待重啟，GUI 重開不自動挖礦。自動重啟使用目前運行的 BAT 設定，僅儲存而未套用的 BAT 變更不會被自動啟動。

## Accepted 平均與逐筆 share 紀錄

- 保留最近 10 分鐘、30 分鐘、1 小時的平均 Accepted（筆／分鐘），新增「整體平均（本次挖礦）」：本次累積 Accepted ÷ 本次實際觀測分鐘。顯示新增筆數及涵蓋時間，重啟礦工重新起算。
- 四組平均值與硬體資訊依同一間隔、同一批次更新，預設 1 分鐘；修改間隔後即套用。成功 share 原文及 Accepted 數字仍即時更新。資料不足或無法確認時段邊界顯示 —。
- 每一行實際收到的成功 share 只寫一筆 `.log`；API 計數不產生假 share，硬體採樣與難度變化不另寫紀錄。**不再保存平均數據**。
- 每筆包含原始 share 文字（含原始空白）、接收時間、原文中的 share 時間、最近一次 API 算力（H/s）及其採樣時間、該行之前最後回報的礦池工作難度與回報時間。難度取自 `Difficulty` 或 `Job received [diff: ...]`，不是網路難度。
- 算力取自最近 API 讀值，不受畫面硬體更新間隔影響；超過 15 秒或尚無資料時為 `null`，不將舊讀值當作即時測量。缺少礦工時間或難度亦為 `null`。即使首批 share 在 API 就緒前收到，仍保存原文，未知算力不補造。
- 挖礦設定新增「成功分享紀錄」資料夾，可輸入完整路徑或用按鈕選擇。留空使用 `%LOCALAPPDATA%\SRBMiner Monitor\MiningLogs`。按「儲存設定」即套用，不需重啟礦工；新 share 寫入新位置，已排入佇列的紀錄及舊檔保留原處，不自動搬移或刪除。
- UTF-8 JSON Lines 格式，以日期及監控程序 ID 分檔：`mining-yyyy-MM-dd-PID.log`。總覽提供「開啟 Log 資料夾」。寫入失敗會顯示提示，背景寫入不阻塞分享接收，正常退出會排空待寫紀錄。

欄位：`timestamp`（接收時間）、`session`（挖礦階段）、`share_text`（原始文字）、`share_timestamp`（礦工回報時間，依本機時區解讀）、`hashrate_hps`、`hashrate_timestamp`、`pool_difficulty`、`pool_difficulty_timestamp`。舊版已產生的 log 保留原格式。

## 礦工停止與非預期關閉計數

礦工停止後不再查詢 API 或 GPU 感測器，也不繼續刷新分享平均值；畫面保留最後讀值。尚未啟動時亦不掃描外部 API。手動或排程重新啟動礦工成功後才恢復監控。已啟用的重啟倒數仍會執行，不會因暫停資料查詢而停止。

總覽顯示本次應用程式運行期間的「非預期關閉」次數，每次運行中的礦工意外退出只加一。手動停止、手動重啟與定時停止不計入；自動恢復成功也不清零。關閉並重新開啟監控應用程式會歸零。API 暫時無法連線不當作礦工關閉。

本版從 0.2.1 延續 0.1.8 分支製作，未改以 0.2.0 為基礎。升級時請先結束舊版，再完整解壓縮 0.2.2。

成功分享即時輸出由 ConPTY 虛擬主控台擷取，需要 Windows 10 1809 或以上版本。礦工明確延後寫出的訊息，仍只能在實際輸出後收到。


## 版本與維護方式

只保留 `main` 開發分支。之後直接在 `main` 更新功能、修正與版本，不另開版本分支。

保留 `v0.1.8`、`v0.2.0`、`v0.2.1`、`v0.2.2` 的 Tags 與 Releases；沒有已發布的 0.1.9。舊開發分支、0.3.0 試作與 0.1.8 以前的版本標籤已廢棄。Git 提交歷史保留。

`main` 使用 0.2.2 的程式行為，並保留 0.2.0 的歷史；已廢棄的 0.3.0 轉接器試作不屬於目前版本。

發布新版時，直接在 `main` 更新應用程式與介面版本、增加 `docs/RELEASE-NOTES-版本.md`，並更新 README 下載連結。推送後會執行核心測試、Windows 整合測試、封裝與 EXE 啟動驗證，再建立對應標籤與 Release。相同版本已存在時只驗證，不覆寫已發布檔案。
